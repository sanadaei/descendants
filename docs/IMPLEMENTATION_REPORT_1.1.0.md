# 実装報告 — 1.1.0

改善1〜6を同じWorldProvider境界とsave schema 1の上で接続した。能力カーブと寿命死、命名専用言語Neral v1、教育・知識伝承・物理的な遺品継承、日次計画による長期進行、分野別研究手順、資源台帳と画面分割を実装した。

## 対応内容

| 順序 | 変更 | 確認した境界 |
|---|---|---|
| 1 | 欠損していた実行成果物、文言テスト、資源引当、遠隔表示を修復 | 引当中の食料が別のロット更新で復活しない。返却後も元ロットの鮮度・由来を維持 |
| 2 | 身体・判断・回復・学習の連続した能力カーブ、独立乱数による寿命死 | 習得技能は減らさない。ロードや通常乱数で寿命は変わらず、健康な高齢者も通常tickで死亡 |
| 3 | Neral v1の人名・世帯の家名・地名 | 子供は第1親の家名を継承。新規命名は保存し、旧名とProviderの正準IDは維持 |
| 4 | 同席する師からの教育・知識伝承、同席する遺族への遺品継承、7/30/365日進行 | 授業と直接行動の時間は労働へ二重計上しない。出生・死亡・危機・手動対応で長期進行を停止 |
| 5 | 対象を特定できる研究に最大15%の分野別改善 | 同分野の効果は加算しない。知識消失で無効化。未特定・低確度の研究は万能な改善を与えない |
| 6 | 描画をcommand/body/knowledge/inventory/chronicle/map/systemへ分離 | 操作・保存・Provider連携はappが保持。旧画面だけにあった現地操作を現在の地図に接続 |

`app.ts` は元の291,523 bytesから約113KBへ削減。画面別ソースを検査する共通読取ヘルパーを導入し、未使用の旧画面と旧ナビゲーションを除去した。テストのためだけに旧ラベルをコメントへ残す方法は使わず、現在のタブと実際の描画関数を検査する。

Neralの例: seed=110004、個人ID=`p`、世帯ID=`h` で `Teri Futoen`。地点ID=`settlement:shared` で `Risuaranar`。音韻・語根・接尾辞・継承規則は [GENERATIONS_AND_NAMING.md](GENERATIONS_AND_NAMING.md) に定義した。

## 維持した設計・影響

- 無期限継続の現行仕様を維持。既存の口承、研究知識を参照する診療・異常現象を残す。
- IncidentはSituationの可視投影を使用。Encounter、Rendezvous、外部紛争を別の因果モデルとして維持する。
- Knowledgeの移行・比較射影は保存互換性とfail-closed読取のため維持する。
- 通常在庫はロット台帳から集計し、Incident資源は元ロットを参照する引当として扱う。旧スカラーとの調整は互換経路に限定する。
- 旧セーブの名前は変更しないが、老化と寿命死は適用する。既に極端に高齢の住民がいるセーブでは、次の進行で死亡が発生し得る。
- 全面技術ツリー、会話用の人工言語、単一の汎用事件モデルへの再構築は実装対象に含めない。
