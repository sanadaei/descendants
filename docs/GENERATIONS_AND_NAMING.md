# 世代・命名の仕様 — 1.1.1

## 改善順序と設計上の判断

1. ビルドの再現性、資源予約と台帳、遠隔表示、既存テストを修復。
2. 習得技能と実効能力を分離し、老化と寿命死を追加。
3. 命名専用の人工言語を固定し、人名・家名・地名へ適用。
4. 教育・知識伝承・物理的な遺品継承・長期進行を接続。
5. 対象に応じた研究の実用効果を追加。
6. 画面別に描画を分割し、移行処理と検証を整理。

現在の設計は無期限の継続を目的とするため、未使用の ending ヘルパーを理由に終幕トリガーを追加しない。既存の口承と研究による治療・異常現象への影響を維持し、欠けていた仕組みを補う。

## 老化と寿命

`aging.ts` は365日を1年として、日内時刻も含めた年齢から線形補間する。数値はゲーム調整用で、医学的な推計ではない。

| 年齢 | 身体 | 判断 | 回復 | 学習 |
|---|---:|---:|---:|---:|
| 6 | 0.35 | 0.30 | 1.105 | 1.15 |
| 20 | 1.00 | 0.854 | 1.00 | 0.996 |
| 35 | 1.00 | 1.00 | 1.00 | 0.969 |
| 55 | 0.85 | 1.00 | 0.85 | 0.867 |
| 75 | 0.55 | 0.91 | 0.575 | 0.70 |
| 95 | 0.25 | 0.75 | 0.35 | 0.50 |

身体技能は身体係数、診療・介護は身体と判断の加重平均、記録・指導・交易は判断係数を使う。労働、移動、遭遇、研究、異常現象試行に実効技能を適用する。回復・疲労・学習にも対応する係数を適用し、習得済みの `skills` 自体は年齢によって減らさない。

寿命は `life-v1`・世界seed・安定した個体識別子・誕生日から独立乱数で導出する。基準は `62 + 34√u + (resilience−50)/10` 年で、resilienceを0–100へ制限する。通常乱数の消費、ロード、時刻刻みの細分化で寿命は変わらない。寿命日の通常シミュレーションで、体力が残っていても一度だけ死亡する。既存の病死・負傷死と共通の死亡処理へ接続し、年代記・後継指導者・日次報告に反映する。寿命日はプレイヤー画面へ公開しない。

## Neral v1 — 命名に使う人工言語

会話文法・翻訳・実在言語の模倣は扱わない。語根の意味は命名用の辞書としてだけ使う。

- 子音: n m l r s t k v f h。母音: a e i o u。
- 基本音節: CV。固有語幹は2音節。接尾辞では末尾n/r/l/sと異なる母音の連続を許す。先頭大文字、同じ母音が結合部で連続すると1音へ縮約。
- 個人名: 固有語幹。家名: 世帯の固有語幹 + `en`。
- 表示人名: `個人名 家名`。子供は第1親の記録された家名を継承し、既存名に家名情報がない場合は同じ世帯の規則から補う。
- 新規集落開始時は全住民に命名。移住交渉のゲーム側個人にも命名し、同一世帯の家名を共有する。Providerが移住者の名前を明示した場合はその名前を維持。
- 地名: 地点の固有語幹 + 地形語根 + 種別接尾辞。

| 語根 | 命名上の意味 | 接尾辞 | 種別 |
|---|---|---|---|
| sela | 水 | nar | 集落 |
| vara | 森・木 | sel | 水系 |
| kara | 石 | tir | 地形 |
| tira | 丘 | ves | 道・経路 |
| lina | 谷 | ar | 地域 |
| mora | 海 | en | 家系 |
| ula / nora / vesa / ara | 原 / 住処 / 渡り / 土地 | | |

例: `generatePersonName(seed, personId, householdId)` と `generatePlaceName(entity)`。語根・接尾辞は版1で固定し、生成は個体ID・世帯ID・地点IDごとに独立。ProviderのID、正準ラベル、由来は書き換えない。新規人名は `naming` に原名も保持し、地名は同じ安定IDからゲーム側表示名として導出する。同名はあり得るためIDが個体・地点の識別子であり続ける。旧セーブは既存の人名・集落名を維持する。

## 教育と継承

3歳以上18歳未満の住民が、同席する成人から1日あたり1時間学ぶ。F2で師と重点技能を選ぶ。成人の授業時間は各区間の25%以内、直接行動の予約時間と授業時間を通常労働から差し引く。師が死亡・不在・重傷なら、同席する親、介護技能、ID順から適任者を選び直す。

子供は習得技能1から始め、両親の技能由来の適性を学習上限として別に保持する。教育は実際の技能を育て、累計24授業時間ごとに師が現に持つ知識を伝える。13歳以降の職業選択は習得技能を参照し、18歳まで教育を続ける。適性は遺伝子の医学的な推計ではない。

死亡者の携行品・装備は、同じ場所にいる子、同じ世帯、ID順の生存者へ移す。装備は外し、継承の記憶を残す。遠隔の遺族へ物資や未通信の死亡記憶を瞬間移動させない。身体にしか保持されなかった知識は死亡時に自動保存されないため、授業・会話・Archiveが継承手段になる。

## 長期進行

F1の7日・30日・365日進行は、既存のDailyPlanのcommit/executeと朝の報告を毎日繰り返す。1日ごとに保存して操作へ制御を戻す。停止操作、出生、死亡、重大な住民状態、手動介入、直接遭遇で中断する。日次ループを迂回せず、未解決の手動介入を自動解除しない。365日を越える連続進行は繰り返し操作する。

## 研究の実用効果

現地観測に保存された種別・資源キー、診療の測定記録、または明示的な旧形式の意味IDから、診療・水管理・採集・修繕・記録・調査準備の分野を選ぶ。opaqueなエンティティIDやアイテムIDの部分文字列を意味として扱わない。確度0.35以上の成果が、確度×15%（上限15%）の作業改善を確立する。診療は同じ処置・病理に紐づく重症度の改善が0.35を超えて測定された場合のみ、治療効果へ改善を付ける。悪化・変化なし・測定なしの成果は知識として保存する。診療の自動選択では同席する患者・担当医または集落が参照できる測定記録だけを使い、悪化を優先度の低下に反映する。研究成果などに同じ観測が複製されても選択の支持を加算しない。一般的な対象不明の仮説に万能な改善を付けない。

研究開始時の確度は根拠の確度×0.65（上限0.8）。作業時間と技能は進捗だけを進め、追加観測なしに確度を高めない。成果の確度は元の根拠を超えない。元の主張が変わった、または失われた計画は中止。制度知ではない根拠の参加保持者が離れた場合、または必要なサンプルが集落から離れた場合は進行を停止する。

同分野の改善は加算せず、現存し制度知として保持される最も強い手順だけを使う。知識が失われれば効果を停止する。F3で手順・効率・適用回数を表示する。これは局所的な手順改善であり、世界の隠れた真実を保証する技術ツリーではない。

## 台帳・UI・互換性

資源ロットが通常在庫の正準モデルであり、スカラー値は集計射影。Incident予約は元ロットIDと数量を保持する引当であり、独立した生産・在庫ではない。返却は元ロットへ戻す。新規資源変更は `adjustResourceStock` または既存のロットAPIを使う。スカラーからの調整は旧セーブ・既存呼び出しとの互換経路として残す。

`app.ts` はイベント・保存・Provider連携・描画コンテキストを担当する。`ui/commandView`、`bodyView`、`knowledgeView`、`inventoryView`、`chronicleView`、`mapView`、`systemView` が画面描画を担当する。IncidentはSituationの可視投影から生成し、既存のdefault OFFを維持。Encounter、Rendezvous、外部紛争は別々の操作・因果モデルとして維持する。異なる正準モデルを一つの重複イベント台帳へ再格納しない。

KnowledgeStoreと射影アダプターは保存互換性とfail-closed読取のために維持する。F3は既存のselectorを経由し、同席する観測者に許される知識・Archive・研究だけを表示する。遠隔F2・人物一覧・索引は現在の身体値・病理・装備・死亡状態を公開しない。

地図推定は保持されたJSON主張から中心と誤差半径を読み、WORLDマーカー・距離・遠征先・移動先へ同じ値を使う。推定地点への正準topology routeは提示しない。直接観測した位置は確認済みとして使う。異常医療は集落に同席する生存者だけを対象とする。

新規フィールドは任意で、save schema 1を維持。保存validatorとreplay hashに命名・教育・適性・研究手順・予約ロットを含める。旧名を改名しない。既存の地図推定は再観測なしで読み取る。観測メタデータを持たない旧サンプルは隠れたProvider情報から補完せず、再観察・再採取で意味を記録する。測定記録を持たない旧医学研究の改善は保存したまま適用を停止し、F3に表示する。旧セーブにも能力カーブと寿命は適用されるため、既に非常に高齢の住民は次の時間進行で寿命死し得る。

## Git checkoutの検証

`npm ci`、`npm run verify`。実行束は不足していた `vendor/i2x-worldgen-runtime/dist` を同梱Worldgen 1.5.0ソース・TypeScript 5.8.3から再構築して固定する。旧manifestに記載された未同梱のバイナリと同一とは主張しない。新しいdigestを検証し、WorldProvider契約の固定SHA-256を従来の値で照合する。統合テストは実際のProvider境界・安定ID・由来・LOD・セーブ復元を検証する。

`release:audit` は通常checkoutの到達可能コード・操作経路・配布物を検査する。ZIPハンドオフの兄弟ファイルとSHA台帳まで検証する場合だけ `node tools/audit-release-surface.mjs --package-root <directory>` を使う。
